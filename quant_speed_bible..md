# SBI PO Quant Speed Bible

**Target: 15/30 → 22+/30**
**Focus: speed, selection, and accuracy**

---

## 1) ONE-PAGE EXAM STRATEGY

### Core principle

In SBI PO Quant, the highest score comes from **picking the right questions fast**, not attempting everything.

### First-pass order

Use the first pass to collect the safest marks.

1. **Simplification / Approximation**
   Fastest return, usually low risk.
2. **Number Series**
   Try only if the pattern is visible quickly.
3. **Quadratic Equations**
   High-scoring if the roots are clean.
4. **Easy DI set**
   Choose only one set with clean numbers and minimal clutter.
5. **Easy arithmetic word problems**
   Pick only the ones you can finish quickly.

### Second pass

Use the second pass only for questions that are still solvable without strain.

* Arithmetic questions you can solve in under a minute
* A second DI set only if the first pass was efficient
* Any question where the method is now obvious

### Immediate skip rules

Skip fast if any of these happen:

* A question does not reveal a method within 15–20 seconds
* A DI set has too many values, too much scanning, or messy comparisons
* A series has no visible pattern after a quick pattern check
* A word problem looks long but gives no direct handle

### Attempting vs skipping

* Do not leave easy marks unattempted because of overthinking.
* If you can reduce a question to **two options**, attempt it.
* Avoid blind guesses when there is no elimination value.
* In Quant, **one wasted hard question can cost more than two easy attempts**.

### Time budget

A practical split:

| Activity                            |    Time |
| ----------------------------------- | ------: |
| Simplification + Series + Quadratic | 6–7 min |
| Best DI set                         | 6–7 min |
| Easy arithmetic                     |   5 min |
| Review / fillers                    |   2 min |

### Golden rule

**Selection > Speed > Accuracy**
The best score is built by selecting the right questions, not by rushing every question.

## 2) APPROXIMATION & CALCULATION SHORTCUTS

### Core idea

Approximation is useful when the options are far apart. You do not need exact answers every time; you need the **correct range**.

### Rounding rule

Round to convenient values without destroying the sense of the expression.

* 48.7 → 49
* 649 → 650
* 2978 → 3000

Use this when the options are separated enough that exact precision is unnecessary.

### Safe approximation habits

* Round one number up and another down only when it helps preserve a clear comparison.
* Keep the error direction in mind.
* Do not approximate aggressively when the options are very close.

### Fast comparison without full calculation

When comparing products or ratios, avoid complete multiplication.

Example:

* 287 × 34
* 312 × 29

Instead of multiplying fully, compare using close values:

* 287 × 34 ≈ 290 × 34
* 312 × 29 ≈ 310 × 29

This is enough to decide the larger expression quickly.

### When approximation is enough

Use approximation when:

* options are widely spaced,
* the question asks for the closest value,
* the arithmetic is long but the answer range is obvious.

### When approximation is not enough

Do not approximate when:

* options are very close,
* the question asks for exact remainder, exact digit, or exact relation,
* the set is designed to trap rough estimations.

### Common approximation traps

* Percentage questions where the denominator matters sharply
* DI values that look close but change the final ranking
* Options differing by a very small margin

### Useful mental conversion habit

Use familiar fraction-percentage relationships to reduce calculation load:

* 1/2 = 50%
* 1/3 ≈ 33.33%
* 1/4 = 25%
* 1/5 = 20%
* 1/6 ≈ 16.67%
* 1/8 = 12.5%
* 3/8 = 37.5%
* 5/8 = 62.5%
* 7/8 = 87.5%

These help in percentage, ratio, profit-loss, and approximation questions.

## 3) TOPIC-WISE QUICK REVISION SHEET

### A. Simplification / Approximation

* Follow BODMAS strictly.
* Approximate after identifying the structure, not before.
* Use nearby round numbers to reduce time.
* Break large calculations into manageable parts.
* If the expression looks long but the options are wide, approximate aggressively.

**Best use case:** easy marks in under 30 seconds.

---

### B. Number Series

Check the most common patterns in this order:

1. Difference pattern
2. Multiplication / division pattern
3. Alternate terms
4. Square / cube based pattern
5. Mixed pattern
6. Two interleaved series

**Fast rule:**
If no pattern appears quickly, do not force one.

For wrong number series:

* Test each term individually
* Look for the odd term
* Do not rebuild the entire sequence unless necessary

**Best use case:** quick pattern recognition.
**Worst use case:** forced guessing.

---

### C. Quadratic Equations

* Use factor method first.
* Look for factor pairs of the constant term.
* Compare roots directly when possible.
* Do not solve fully if the relation is already clear.

Fast outcome possibilities:

* x > y
* x < y
* x = y
* x ≥ y
* x ≤ y
* no relation

**Trap:** sign mistakes, especially with negative terms.

---

### D. Data Interpretation

* Spend the first few seconds understanding the structure.
* Identify what is being asked before touching the numbers.
* Use rounded totals when exact precision is not necessary.
* Use ratio-based comparisons wherever possible.
* Avoid reading every value repeatedly.

**Common DI traps:**

* Mixing totals with percentages
* Confusing “increase” with “increase in percentage”
* Over-calculating a value that the options already narrow down

**Best use case:** one clean set with direct questions.
**Worst use case:** cluttered caselets and dense comparisons.

---

### E. Percentage

* Convert percentage changes into a multiplication factor.
* Use successive change only when necessary.
* Reduce repeated percentage operations into one expression.

Quick logic:

* Increase by x% → multiply by (1 + x/100)
* Decrease by x% → multiply by (1 - x/100)

For successive changes:

* Use the combined effect rather than handling each change separately.

---

### F. Profit & Loss

* Tag CP, SP, MP clearly as soon as the question starts.
* Apply the percentage factor directly.
* Do not confuse marked price with selling price.
* If discount is part of the question, treat that as the main layer before profit-loss.

**Trap:**
Doing the entire problem from scratch when only a simple percentage factor is required.

---

### G. Simple Interest / Compound Interest

* SI is linear.
* CI grows faster because interest is added to interest.

Useful quick relation:

* Difference between CI and SI becomes relevant when the number of years is small and the rate is fixed.

**Trap:**
Using the full compound formula when the question asks for only a difference or a comparison.

---

### H. Ratio & Proportion / Partnership

* Convert ratios into a common base.
* Partnership problems are investment × time problems.
* Always multiply investment by time before comparing shares.

**Trap:**
Using ratio alone when time is part of the partnership setup.

---

### I. Time, Speed & Distance

* Convert units immediately.
* Use relative speed for motion problems.
* Average speed is not always the simple average.

Useful rule:

* Same distance, different speeds → use the harmonic-type formula, not arithmetic mean.

**Trap:**
Forgetting unit conversion between km/h and m/s.

---

### J. Time & Work

* Think in terms of efficiency, not days.
* Convert work into “work per day”.
* Add efficiencies, not days.

**Trap:**
Trying to combine days directly instead of converting to work rates.

---

### K. Mixture & Alligation

* Use alligation when the question is about mixing two quantities at different values.
* Cross-method is faster than setting up equations.

**Trap:**
Using brute-force algebra when the weighted average method is enough.

---

### L. Permutation / Combination / Probability

* Use direct formulas only when the structure is clear.
* Reduce the sample space first.
* Simplify counting logic before calculating.

**Trap:**
Expanding factorial expressions unnecessarily.

## 5) TIME-SAVING METHODS FOR ARITHMETIC

### Use structure, not calculation

When a question looks lengthy, first ask:

* Can I convert it to percentage?
* Can I convert it to ratio?
* Can I convert it to efficiency?
* Can I compare using options?

### Use decomposition

Break complex values into neat parts.

Example:

* 98 × 103
* Treat as (100 - 2)(100 + 3)

This is much faster than direct multiplication.

### Use option-based solving

If options are present:

* work backward,
* compare approximate values,
* eliminate impossible options early.

### Use logic over brute force

* Sign
* Parity
* Range
* Magnitude

These are often enough to remove 1–2 options instantly.

## 6) SMART SKIP STRATEGY

Skip a question if:

* no method appears in 15–20 seconds,
* the question is calculation-heavy with no shortcut,
* the pattern is unclear,
* the data set is too dense,
* the risk of waste is higher than the expected gain.

Do not skip if:

* the method is known but the calculation is slightly long,
* one or two steps are enough to finish,
* the question can be attacked from options.

### Good skip signals

* Re-reading the same line twice without progress
* Multiple moving parts with no clear anchor
* A DI set that needs excessive scanning
* A series that still looks random after a quick pass

### Good attempt signals

* Clean equations
* Visible ratio structure
* Direct percentage relation
* A pattern that is obvious within seconds
* A DI set with simple numbers and stable comparisons
